# Сервис бронирования переговорок

Сервис поднимается через Docker Compose, слушает порт **8080**. Спецификация API: [api.yaml](api.yaml), условие: [TASK.md](TASK.md).

## Расписание и слоты (30 минут)
- расписание создается один раз, после не изменяется (на ближайшую неделю) -- чтоб не хранить большой объем данных, плюс в реальной жизни такого периода планирования вполне достаточно
  длительность слотов одинакова и фиксирована - 30 мин
  слоты не хранятся на окно из многих дней а отдаются on-demand на запрошенную дату
- быстро работает за счёт индекса по `(room_id, start_ts)`  

## Создание ссылки на конференцию при бронировании
- если проблемы с внешним сервисом или ошибка была до получения ссылки - бронь создается без нее
  В ответе заголовок `X-Booking-Warning` с пояснением
- если сервис вернул ссылку но не получилось сохранить в БД - бронь остается без ссылки, клиент получает предупреждение в `X-Booking-Warning`

--- Идемпотентный повтор создания брони невозможен без отмены
Повторный вызов отмены бронирования возвращает 200 OK

## Тесты

- юнит-тесты бизнес-логики: `internal/domain`, `internal/usercase/...`, `pkg/apperrors`, обработчики без БД
- интеграционные (E2E против поднятого сервиса): в `internal/app/e2e_test.go`

Запуск тестов:

```bash
go test -v ./... -cover
```

Покрытие по пакетам:

```bash
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out | grep total
```
